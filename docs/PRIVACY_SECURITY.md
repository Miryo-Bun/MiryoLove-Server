# Технические меры защиты

## Реализовано в коде

- Пароли хешируются Argon2id; raw session token хранится только в HTTP-only cookie, в PostgreSQL сохраняется HMAC hash.
- Cookies: HttpOnly, SameSite=Lax, Path ограничен API, Secure при `NODE_ENV=production`; OAuth state одноразово сверяется с отдельной короткоживущей cookie и очищается после callback.
- Защищённые API используют серверную аутентификацию. Операции с чатом фильтруются по `userId`; JSON-поля проверяются Zod; JSON body имеет лимит.
- Helmet, точный allowlist CORS/Origin, rate limits для auth, сообщений и AI; единый ответ ошибки не возвращает stack trace.
- HTTP-логи содержат method, безопасный шаблон маршрута, status, duration и случайный request ID; динамические значения path, query, body, IP, cookie и текст сообщения не пишутся middleware. Неизвестные маршруты логируются как `unmatched`. AI stderr не журналируется как свободный текст; дочерний процесс получает whitelist окружения без DB URL, session secret и OAuth-секретов.
- `DELETE /api/users/me` после удаления аккаунта очищает session cookie; API-тест проверяет отзыв сессии, отсутствие доступа к чужому аккаунту и удаление связанных тестовых чатов.
- AI runtime сохраняет последовательную генерацию, но ограничивает число одновременно выполняющихся и ожидающих запросов значением `AI_MAX_PENDING_REQUESTS` (default 5, max 100). Превышение возвращает `503 AI_RUNTIME_BUSY`.
- Поиск по workspace не обнаружил вызывающих legacy `POST /api/chat`; frontend использует `/api/ai/chat`, а `app.py` не входит в Compose. Его возможный ручной/внешний запуск не проверен. Прямой запуск файла ограничен loopback, но внешний ASGI bind может изменить границу; endpoint не удалён до подтверждения владельцем.

## Ограничения и остаточные риски

- Rate limit и лимит очереди AI находятся в памяти одного процесса; это не общий лимит для нескольких инстансов и сбрасывается при рестарте.
- Нет CSRF token; браузерная защита опирается на SameSite=Lax и Origin allowlist. Не ослаблять проверку Origin при изменении deployment.
- TLS termination, firewall, reverse proxy, публичные порты приложения и внешнее логирование в этой проверке не подтверждены.
- PostgreSQL соединение локального приложения не использовало TLS. DB login является SUPERUSER/CREATEDB/CREATEROLE; изменение прав отложено, чтобы не сломать работающий сервер.
- Пошаговые планы least-privilege перехода/отката и TLS с проверкой CA/hostname подготовлены в [DATABASE_SECURITY.md](DATABASE_SECURITY.md); production DB, TLS и Compose не менялись.
- Скрипт backup проверяет, что passphrase не находится в каталоге архивов, и не удаляет старые архивы автоматически. Ключ и архив по умолчанию остаются на одном хосте; off-host копия и сроки хранения не настроены.
- После совместимых обновлений и проверенного override `minimatch` команды `npm audit` и `npm audit --omit=dev` сообщают 0 уязвимостей.
- Python runtime/модель находятся вне этой рабочей директории; их зависимости, код и настройки необходимо отдельно проверять. Не запускайте legacy FastAPI на публичном интерфейсе.
- Не задана политика ротации логов. Docker Compose не содержит application container, read-only filesystem или resource limits.

## Конфигурация и секреты

`.env` имеет права `0600`, не отслеживается Git; содержимое не выводилось. Секреты не помещаются в репозиторий. Compose требует явный `POSTGRES_PASSWORD`; в проверенной `.env` соответствующий ключ отсутствовал. Compose config проверен только с непроизводственным одноразовым значением, production secret не менялся. До любого применения владельцу/DBA необходимо безопасно согласовать действующий credential с существующим volume; не перезапускать БД с неподтверждённым паролем.

## Проверки оператора

Внешняя оценка модели угроз, применимые меры по уровням защищённости, локализация, договоры с обработчиками, аудит инфраструктуры, права администраторов и порядок тестирования на уязвимости требуют отдельного решения владельца и профильного специалиста.
