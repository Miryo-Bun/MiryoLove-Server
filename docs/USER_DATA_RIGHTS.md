# Запросы субъектов и операции с данными

## Поддержка в API

- `GET /api/users/me` — прочитать публичный профиль текущей учётной записи.
- `PATCH /api/users/me` — изменить display name и/или HTTPS avatar URL.
- `DELETE /api/users/me` — аутентифицированный пользователь удаляет собственную учётную запись; endpoint отзывает серверную сессию и очищает cookie в ответе.
- `POST /api/auth/logout` отзывает текущую сессию.

Владелец должен определить канал приёма/подтверждения личности, полномочия исполнителя, сроки и журнал исполнения обращений. API не является полноценным workflow обращений субъекта и не экспортирует все записи пользователя.

## Удаление аккаунта

Удаление `User` полагается на существующие FK `ON DELETE CASCADE`: удаляются OAuth accounts, sessions, chats, messages и их sources. Endpoint не меняет чужие записи. Перед реальным запросом следует разъяснить последствия и подтвердить намерение согласно утверждённому процессу. Операция не удаляет архивы резервных копий, хостовые логи и копии у внешних обработчиков. Фоновая очистка копий не реализована; сроки их выбытия должны быть указаны в утверждённой политике.

Прямое удаление необратимо для основной БД. Не использовать endpoint на тестовых/чужих аккаунтах; тесты используют in-memory doubles. Заявления об абсолютном удалении допустимы только после оценки всех копий и правовых оснований хранения.

## Не реализовано

Самообслуживаемый экспорт, подтверждение email, password reset, административный workflow обращения, исправление иных атрибутов субъекта и purge сообщений по расписанию отсутствуют. Не добавлять массовое удаление без отдельного анализа retention и правовых обязанностей.
